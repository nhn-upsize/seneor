# 분기 보고서 작업 가이드

**이 문서의 목적: 담당자가 바뀌어도 같은 프레임·같은 기준으로 이어서 만들기.**

새 분기 작업은 **새로 만드는 게 아니라 기간을 연장하는 것**입니다.
프레임(탭·섹션·차트 종류)은 그대로 두고, 기간만 늘려 추세를 이어 봅니다.

작업 전에 이 문서와 [`report_pipeline/README.md`](../report_pipeline/README.md) 를 먼저 읽으세요.

---

## 1. 절대 바꾸지 않는 것

아래는 분기가 바뀌어도 **그대로 유지합니다.** 바꾸면 이전 분기와 비교가 깨집니다.

### 1-1. 보고서 프레임

| | |
|---|---|
| 본편 탭 4개 | ①국가별 모바일 시장 분석 ②KR 모바일 웹보드 장르 분석 ③국가별 신규 진입 게임 분석 ④데이터 기준·집계 명세 |
| 국가 | KR · JP · US (3국 고정) |
| 국가별 섹션 | ①매출 변화원인 ②퍼블리셔 국적별 ③장르별 ④퍼블리셔 국적×장르 ⑤대표 게임별 ⑥자국 퍼블리셔 |
| 파일 | 본편 `index.html` · 요약본 `summary.html` |

⑦ 계절성 섹션은 2026-07 사용자 지시로 **3국 모두 제외**했습니다. 요청 없으면 다시 넣지 마세요.

### 1-2. 집계 표준

- **OS 통합** — `dw_app_monthly` 의 `in_revenue_top100_unified_os = TRUE`, 앱 중복은 `unified_app_id` 로 제거.
  OS별 분리 뷰는 **명시적으로 요청받았을 때만** 추가
- **매출** — `revenue_krw_100` (환율 반영 완료 컬럼. 쿼리에서 환율 계산 불필요)
- **월평균 분모 = 달력 개월수 고정** (활동월 수로 나누지 않음).
  연 12 · 부분연도는 그 개월수 · 전 36 · 후 18.
  → 각 장르·국적 행의 합이 합계와 정확히 일치해야 합니다(자기정합)
- **연평균은 월별 SUM 후 평균.** `GROUP BY name` 뒤 `AVG` 를 쓰면 iOS/Android 이중 카운트로 50% 틀립니다
- **QoQ%** — Q1 = 1~3월 월평균, Q2 = 4~6월 월평균 기준

### 1-3. 퍼블리셔 국적 5분류

`KR / JP / 중화권 / 북미 / 기타`

- **NEXON → KR** 강제 (JP 등록이지만 KR로 집계)
- **FUNFLY → 중화권** 강제
- **중화권 = China · Hong Kong · Taiwan · Macao 만.**
  **싱가포르는 절대 중화권에 넣지 않습니다.** Garena·Omnilojo 등은 "기타".
  유일한 예외가 위 FUNFLY 하나입니다.
  → 2026-07에 싱가포르 전체를 중화권으로 넣었다가 정정한 이력이 있습니다.
    `report_pipeline/config.py` 의 `CHINA_REGION` 에 Singapore를 다시 넣지 마세요.

### 1-4. 장르

- 표준 장르 = KR은 `COALESCE(lv2_genre, sub_genre, genre)` / JP·US는 `COALESCE(lv2_genre, genre)`
  (KR만 RPG를 MMORPG / 비MMORPG로 분리)
- lv2 특수버킷 4종: `웹보드(PvP)` `Casino(PvE)` `방치형` `머지`

### 1-5. 항목 선택 기준 (차트에 어떤 장르·조합을 올릴지)

**Q2 매출 상위 5 + QoQ 감소 상위 3 + 증가 상위 3 의 합집합**, **절대금액(억원) 기준.**

- 퍼센트 기준으로 뽑지 마세요. 매출이 작은 항목이 끼어들어 왜곡됩니다
  (KR Racing: -4.7억인데 -20%로 상위에 올라온 사례)
- 개수가 통상 7~10개에서 벗어나도(예: US 6개) 기준에 맞으면 그대로 둡니다.
  **개수를 맞추려고 왜곡된 항목을 넣지 마세요**
- 감(느낌)으로 고르지 말고 기준을 명시적으로 적용하세요.
  JP에서 매출 2위인 Strategy를 빠뜨렸다가 지적받은 이력이 있습니다

### 1-6. 부분 분기 게임 평균

- **개별 게임 하나만 볼 때** (⑤ 대표게임별 등): 활동월 수로만 나눔.
  3월 출시면 Q1 평균 = 3월 매출 그대로
- **장르·퍼블리셔 등 카테고리 합계**: 카테고리 월별 합계를 먼저 낸 뒤 3으로 나눔.
  중간에 신규 게임이 있어도 그 달 이전은 0으로 자연히 포함
- 게임별로 먼저 평균 낸 뒤 합치면 카테고리 총계가 국가 전체 매출과 안 맞습니다
  (KR 방치형에서 -273억이 -372억으로 부풀려진 사례)
- **규칙은 이대로 유지하고, 헷갈리는 건 라벨로 설명합니다** —
  `(3월~,1개월)` `(6월신규,1개월)` `(5월결측·2개월평균)` 식으로 차트 라벨에 표기.
  2026-07 사용자 결정입니다. 규칙 자체를 바꾸지 마세요
- 상단 "주요 변화 원인" 박스에는 **게임별 금액을 쓰지 않고 게임명만** 나열합니다
  (게임 기준과 카테고리 기준은 분모가 달라 더하면 안 맞음).
  카테고리·그룹 총계 금액은 그대로 씁니다

## 2. 새 분기 만드는 순서

### 2-1. 기간 연장

`report_pipeline/config.py` 의 **PERIOD 블록만** 수정합니다. 다른 파일은 건드리지 않습니다.

```python
FULL_YEARS = [2022, 2023, 2024, 2025]
PARTIAL = {"label": "26.1H", "start": "2026-01-01",
           "end_exclusive": "2026-07-01", "months": 6}
POST    = {"full_years": [2025], "include_partial": True, "months": 18}
```

3분기(26.1~9월)로 늘린다면 `PARTIAL` 을 `26.1~3Q` / `end_exclusive: 2026-10-01` /
`months: 9` 로, `POST["months"]` 를 `12 + 9 = 21` 로 바꿉니다.

26년이 다 차면 `FULL_YEARS` 에 2026을 넣고 `PARTIAL` 을 27년으로 옮깁니다.

> `months` 는 **달력 개월수**입니다. 실제 데이터가 있는 달 수가 아닙니다.

### 2-2. 데이터 재산출

```bash
python -m report_pipeline.dump_sql
```

→ `queries/generated/<기간>/` 에 13개 섹션 SQL이 파일로 떨어집니다.
이걸 DB에 돌려 값을 얻고 HTML을 갱신합니다. **수기 추정이나 눈대중 금지.**

`generated/` 안의 파일은 손으로 고치지 마세요 — 다음 덤프 때 덮어써집니다.
쿼리 로직을 바꿔야 하면 `report_pipeline/queries.py` 를 고칩니다.

**파이프라인이 커버하지 않는 섹션** (시장총계 일부·퍼블리셔·장르·웹보드·신규진입)은
아직 수동입니다. 실제로 쓴 SQL을 `queries/manual/` 에 섹션별로 뽑아뒀습니다(22개 파일).
**기간이 쿼리 안에 하드코딩**돼 있으니 날짜를 직접 늘려야 합니다.
정본은 `verify/*.py` 이고, 그걸 고쳤으면 `python -m report_pipeline.extract_manual_sql` 로
사본을 다시 뽑으세요. 자세한 지도는 [`queries/README.md`](../queries/README.md).

### 2-3. 발행

`README.md` 의 "새 분기를 추가할 때" 4단계를 따릅니다
(폴더 생성 → `<title>` → 루트 리다이렉트 → `reports.html`).

## 3. 검증 — 여기를 건너뛰지 마세요

### 3-1. 자동 검증

```bash
python -m report_pipeline.validate
```

**`✅ 0건` 이 될 때까지 고친 뒤 발행합니다.** DB 없이 HTML만으로 돕니다.

- `[C1]` ②국적별 표: 메인 = TOP5 + 기타 (전 컬럼)
- `[C2]` 한눈에 카드 = 헤드라인

검사를 늘리려면 `validate.py` 의 `CHECKS` 에 함수를 추가하세요.

### 3-2. 손으로 봐야 하는 것

자동 검증이 못 잡는 것들입니다. **전부 실제로 틀렸던 적이 있습니다.**

1. **상단 요약박스 ↔ 하위 섹션 대조** — 같은 수치가 카드·배너·표·해설 5~6곳에 복제돼 있습니다.
   한 곳만 고치고 나머지를 놓치는 게 가장 흔한 사고입니다
2. **hbar 차트와 trend 라인차트의 항목 집합 일치** — 개수를 먼저 세서 비교하세요.
   KR·JP·US 전부 이 실수가 있었습니다
3. **차트 수치를 바꾸면 같은 섹션 본문도 함께** — `interpretation` 문구,
   `evidence-list`, 💡 요점 summary, 섹션 헤드라인, 차트 라벨
4. **기존 값이 맞는지 먼저 확인** — 다르다고 바로 덮어쓰지 마세요.
   싱가포르 건은 기존 값이 맞았고 제가 고친 쪽이 틀려서 3국 전부 원복했습니다

### 3-3. 앱 이름 함정

같은 게임이 표기 변형으로 여러 리스팅이 되어 있습니다. **합쳐야 하는 것:**

- `Last War:Survival` / `Last War: Survival Game`
- `プロ野球スピリッツA` / `プロ野球スピリッツＡ` (전각·반각)
- `DoubleDown Casino Vegas Slots` / `DoubleDown™ Casino Vegas Slots`
- DQ워크, 퍼즐앤드래곤즈도 같은 패턴

**합치면 안 되는 것 (별개 앱):**

- `한게임 포커` / `한게임포커 클래식` / `한게임 더블에이 포커`
- `FC 모바일` / `EA SPORTS FC Online M`
- `컴투스프로야구V26` / `컴투스프로야구2026` (V26만 사용)
- `Coin Master` / `Coin Master - Board Adventure`

> ILIKE 패턴을 쓰기 전에 **항상 `DISTINCT name` 으로 먼저 확인**하세요.

### 3-4. 알아둘 것

- `date` 컬럼을 JSON으로 보면 전날 15:00Z로 보이는 타임존 표시 아티팩트가 있습니다.
  **`date + interval` 로 보정하지 마세요.** `EXTRACT` / `to_char` 는 이미 정확한 KST 월을 돌려줍니다
- ARPMAU는 **분기 평균매출 ÷ 분기 평균MAU** 가 표준입니다.
  월별 반올림값을 평균내면 값이 갈립니다

## 4. 이 문서를 고쳐야 할 때

기준이 바뀌는 결정이 나오면 **여기와 `report_pipeline/config.py` 를 같이** 고칩니다.
한쪽만 고치면 다음 담당자가 반대 규칙을 따르게 됩니다 —
싱가포르 건이 정확히 그렇게 어긋나 있었습니다(문서엔 제외, config엔 포함).
